## Fix (per workstream FIX DIRECTION)

Make the never-started reap lane-aware: pause reaping (candidate excluded) when the
candidate run's workflow assignment owner agent is ONLINE with a FRESH heartbeat AND
has another run actively executing (status='running', started_at set) on its lane.
The paused run stays pending/queued through lease rotation and leases at succession.
Conservative fallbacks reap as before: no assignment (orphan/standalone runs), owner
has no overseer row, owner offline, stale heartbeat (heartbeat reaper then frees the
lane), or lane idle (no running sibling). A wedged sibling can never hold the pause
beyond its own heartbeat lifetime because the CRI-142 heartbeat reaper frees the lane.

- `reap.NeverStartedCandidates` gets a `heartbeatBefore time.Time` bound and a
  lane-busy NOT EXISTS gate (shared by both engines and both scan stages).
- `store.ReapNeverStartedRuns(ctx, now, createdBefore, heartbeatBefore)` signature
  gains the heartbeat bound; sqlite + pg engines thread it through reader-scan and
  in-tx re-validation.
- `cmd/castle/main.go` derives the bound like the heartbeat reaper
  (agentHeartbeatInterval x runReapMultiplier) and passes it to the never-started pass.
- Suite: existing never-started/refire-requeue tests updated for the signature, plus
  (1) a gate-arms matrix test (busy+fresh pauses; offline / stale heartbeat / idle
  lane / no overseer row / no assignment all reap) and (2) the regression test:
  two assignments on one agent lane, first run busy past >3 lease rotations and
  multiple never-started windows -> second survives every pass, then leases and
  executes after the first run ends (succession).

## Reviewer remediation (2026-11-10)

Two blocking defects in the first implementation:

- **B1 — wrong lane keying.** The gate joined `overseers` on
  `workflow_assignments.owner_criteria_id` (the *submitter*). Board-fired
  assignments are submitted under trigger identities
  (`SubmitProjectAssignment` → `OwnerCriteriaID` = trigger id), and triggers
  never get `overseers` rows — so the pause never fired for the exact KB-371
  population.
- **B2 — pause dies at the succession point.** The gate required a sibling
  run `status='running' AND started_at IS NOT NULL` on every pass. Castle
  re-dispatches requeued assignments only via ExpireLeasesNow (2.5 min tick,
  effective after the 5 min lease TTL), while the never-started reaper ticks
  every 15 s: between sibling completion and the successor's RunStarted the
  queued run was reaped in the gap.

### Chosen fix — dispatch-eligibility pause (reviewer B2(b) option 1)

A candidate run is exempt iff its workflow assignment (1:1 via `run_id`) is
still `queued` or `leased` AND dispatch to a live executor is still possible:

- `queued`: EXISTS an online overseer with `last_seen_at > heartbeatBefore`
  that could take the work — global for unscoped assignments, or via
  `project_members` for project-scoped ones. Mirrors the lease scan's own
  eligibility and keys the lane on the **executing** path (membership),
  never on the submitter — board-fired assignments pause like any other.
- `leased`: EXISTS an online fresh overseer matching `a.leased_criteria_id`
  (the holder). A dead executor's stale lease does not stay immortal.
- Terminal/rejected assignments, offline or stale-heartbeat agents, holders
  gone, and no-eligible-member projects reap by timer exactly as before.

This single rule covers busy-lane occupancy AND the succession gap: after
the sibling finishes, the assignment sits queued with a live eligible agent
until the designed dispatch grants it — stays exempt through the gap.

Liveness is heartbeat-freshness only (a wedged-but-heartbeating sibling
holds the pause; freed by CRI-142 once the heartbeat goes stale). Zero
staleness bound (run reaping disabled) passes `heartbeatBefore = now`, which
nothing beats → pause disabled.
